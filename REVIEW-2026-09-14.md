# UI/UX/Feature Audit: ChaosPatch
**Date:** 2026-09-14
**Version audited:** v0.38.0
**Scope:** UI, UX, and features (focused audit — patch 7ed91d64). Architecture/infra only flagged where it surfaced.

## Executive Summary

The May 2026 review's big items are fixed: single-patch queries now scope by `userId`, MCP inputs go through Zod (`lib/mcp-schemas.ts`), priority badges have light variants and live in one module, the add-form empty state names the right tool, and the manifest uses brand colors. The interior is feature-rich (23 MCP tools, bulk select, archive, tags, due dates, attachments, markdown notes, insights).

What's left is mostly **UX friction around finding and acting on a single patch**: nothing links to a specific patch, filter state evaporates, the project page can't search, and failed writes fail silently. Those hit the ND lens hardest: lost state and missing feedback are the two things that break flow.

## High Priority

### 1. Patch mutations fail silently
- **What:** `app/projects/[slug]/patch-list.tsx` (`saveEdit`, `advance`, `reopen`, `addNote`, `remove`, `toggleArchive`) and `project-patch-view.tsx` (`bulkAction`, `archiveCompleted`) never check `res.ok`. `saveEdit` closes the editor regardless, so a failed save throws away the user's typed notes/spec and the row snaps back with no message. (Carried over from May #10 — still open.)
- **Why it matters:** Lost typed work + no feedback. Worst ND failure mode.
- **Action:** Check `res.ok`; on failure keep the editor open, show an inline error on the row. Same for bulk bar.
- **Effort:** Half-day.

### 2. Nothing links to a specific patch
- **What:** Dashboard cards (`patch-list-item.tsx`), the flat Patches view (`home-content.tsx` `PatchRow`), and search results all link to `/projects/[slug]`, where the target patch is collapsed among the rest (and hidden entirely if done → "Completed" section is collapsed by default). Agents cite patches by ID; there's no URL that opens one.
- **Why it matters:** Click "In Progress: X" → land on a list → hunt for X. Breaks the one-click path the dashboard implies.
- **Action:** Support `/projects/[slug]?patch=<id>` — auto-expand the row, open the containing collapsible section, scroll into view, brief highlight. Point all cross-links at it; add a "copy link" next to the ID chip.
- **Effort:** Half-day.

## Medium Priority

### 3. Filter / sort / view state is ephemeral
- **What:** `home-content.tsx` and `project-patch-view.tsx` hold view, status, priority, tag, project, search and sort in `useState`. Navigating into a project and back resets the dashboard to "Projects" view with no filters.
- **Why it matters:** Re-applying the same filters every time is repeated friction; state persistence is a core ND affordance.
- **Action:** Mirror filter state into URL search params (shareable + survives back/refresh).
- **Effort:** Half-day.

### 4. Project page has no search
- **What:** Home's Patches view has text + ID-prefix search; `/projects/[slug]` has only status/priority/tag chips. Projects with many patches (and agents citing IDs) need it most here.
- **Action:** Reuse the home search predicate (title/notes/tags/ID prefix) in `ProjectPatchView`. Pairs naturally with #3.
- **Effort:** Quick fix.

### 5. Floating header likely overlaps `/add` and `/settings`; settings back-link goes to landing
- **What:** `AppHeader` is `fixed top-4`. `/projects/[slug]` compensates with `pt-16` and dashboard/insights with `pt-20`, but `app/add/page.tsx` and `app/settings/page.tsx` have no top offset, so their breadcrumb headers sit under the pill (unverified visually — worst on mobile). Settings' "← Projects" links to `/` (marketing landing) instead of `/dashboard`.
- **Action:** Add the same top offset; point the back link at `/dashboard`.
- **Effort:** Quick fix.

### 6. Bulk select only does start / complete / reopen
- **What:** `app/api/patches/batch/route.ts` accepts three actions. No bulk archive, delete, priority change, or tag add — the things you actually want after selecting 10 stale patches.
- **Action:** Extend batch actions (archive, delete w/ confirm, set priority, add tag) in API + bulk bar + `cp_batch_update` for parity.
- **Effort:** Half-day.

## Low Priority / Nice-to-Have

### 7. No loading / error / not-found boundaries
- No `loading.tsx`, `error.tsx`, or `not-found.tsx` anywhere in `app/`. Dashboard fires 4 parallel queries with no skeleton; a DB error shows Next's default page; a bad slug shows the default 404 with no way back.
- **Effort:** Quick fix–half-day.

### 8. Polish batch
- Header icon links (Insights, Settings, theme toggle) use `title` only — no `aria-label` (May #12, still open).
- Danger zone says "delete all N patches" using `patches.length`, which excludes archived patches that also get cascaded.
- `layout.tsx` `themeColor` (`#EDF4FF` / `#240202`) doesn't match `manifest.json` (`#1E1830` / `#88739E`) — pick one source after the theme change.
- **Effort:** Quick fix.

### 9. Keyboard shortcuts are undiscoverable
- Only ⌘N (add patch) and ⌘P (new project) exist, and nothing in the UI mentions them. No `/` to focus search, no `?` help overlay.
- **Effort:** Quick fix.
